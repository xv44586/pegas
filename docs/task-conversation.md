## 用户结果与验收

用户从最近的事情，以及详情中的补充要求/补充信息入口进入独立事情页。已有回复的详情继续沿用 DESIGN-009 的就地引用回复。原有明确的“查看详情”入口和 `?channel=` 历史链接继续保留详情抽屉，兼容审批、调用链、协作等深入查看。页面展示服务端确认属于当前事情的用户输入、Agent 回复及所有已保存的执行活动，按创建时间混排。下方输入持续指向该事情，右侧可展开概览、交付、执行记录、设置。

1. 事情历史包含最初输入、续接输入、附件和 Agent 回复；超过 200 条输入可分页追溯，不使用全局最近消息过滤冒充完整历史。分页追加去重，失败可重试；刷新不能丢已加载历史或让旧响应覆盖新事实。
2. 发送文字、引用回复、语音与附件沿用既有发送合同；普通续聊明确携带 taskId，发送后不取消当前事情归属。主聊天与各事情草稿隔离，切换事情、网络失败不丢草稿，不把失败消息改投其他事情。
3. A/B 事情切换不显示其他事情的历史；稳定 URL 支持刷新与前进后退；目标不在全局最近列表时也能按 ID 读取。读取失败显示错误与重试，不降级为主聊天。
4. 事情内移除指向自身的事情链接、重复事情标题、事情托盘与可取消的续聊横幅。保留文件、产物、相关事情和必要决策入口；去掉逐条追问与回到发起消息箭头，旧版已保存的引用草稿仍可恢复发送。
5. 右侧复用 Goal/Review Pack/Run/WorkerProfile 等既有数据；没有目标或证据时如实显示空态，不生成业务阶段、标准满足状态、附件汇总、文件版本树或独立工作区承诺。
6. 已完成续接、已停止只读、等待审批与未知副作用核对均服从既有服务端合同；客户端不能通过新页面绕过门禁。传输回执只作为状态，不伪造 Agent 确认。
7. 自动化覆盖跨事情隔离、超过 200 条历史、重试与游标、连续定向发送、草稿、深链及停止态；在本 worktree 运行完整 `pnpm check`、`pnpm smoke`，并验证桌面/窄屏交互。

## 非目标

不新增 Task/Run 状态、业务阶段或文件管理模型；不修改 Router 的归属策略、执行权限、审批政策与恢复授权；不实施跨设备草稿同步；不承诺恢复源端未保存或已截断的执行内容；不直接发布或替换当前运行版本。

## 数据与权限边界

事情页是服务端 Task/Conversation 的客户端投影。历史经 owner 校验，输入沿用 Durable Inbox 幂等键。详情数据读取互相独立，失败不阻断已可读对话；草稿是本地呈现数据，不成为服务端事实。Goal 标准与 Review Pack 满足结论分离；工作范围文字不作为工具授权。设置的有效值与本次 Run 快照分开显示。

`TaskConversationPage` 按 taskId 独立挂载，使用 `?task=` 深链与浏览器历史；读取错误不会回退全局聊天。5 秒轮询完整投影，发送后立即刷新；新请求取消旧请求，切换页面后的响应不可覆盖当前事情。右侧在宽屏为侧栏、窄屏为有焦点约束的 Dialog，预览打开前关闭窄屏面板。顶部图标切换展开/收起，侧栏内另有关闭按钮；关闭后保留当前 tab，焦点返回顶部图标。

服务端唯一新增投影分支是：尚未归属的 pending/processing/failed 引用输入，按 Outbox 的 taskId 和相同 userId 进入事情历史；已有 task_events 关联始终优先。没有数据库迁移，没有修改 Router 或执行权限判断。

## 失败、恢复与回滚

历史/详情加载失败保留最后成功数据并提供重试；切换目标使旧请求失效。发送响应丢失时沿用同一消息幂等键重试，服务端已接收而刷新失败不得再次发送。已停止目标保留历史，不自动新建或改投事情。无数据库迁移；回滚代码恢复旧客户端入口，既有 Task、输入、消息和证据不变。
