# Voice Output

> Feature：`VOICE-002`
>
> 状态：Planned（需求登记，尚未实现）
>
> 更新日期：2026-11-22

## 用户结果

同一个对话可在屏幕渲染器与语音渲染器之间无缝切换，事实与权威不变。语音不是「把屏幕念出来」，而是同一份投影合同（`CONV-006`，见 `docs/conversation-projection.md`）的听觉渲染：say 逐句播报可打断、work 完成才一句话摘要、decide 显式一问一答。TTS 默认系统/浏览器内置、零配置可用，可自定义端点并在失败时回退内置。为未来智能音箱/玩具等语音唯一途径渠道预留同一合同。

## 服务边界

```text
Conversation Event + 投影属性 (lane/anchor/weight, CONV-006)
  -> VoiceProjectionRenderer（按 lane/weight 生成话语队列）
  -> SpeechSynthesisProvider（默认内置 / 自定义端点，失败回退内置）
  -> 播报（可打断、可重播、节点级消费游标）

用户口头回答
  -> VOICE-001 ASR -> 普通 user.message / decide 状态机匹配
  -> 既有服务端 decide 迁移（与屏幕点击同一权威）
  -> 高风险经受认证 confirmation（APPROVAL-001）
```

- 语音输入复用 `VOICE-001`（ASR → 普通 `user.message`，音频不持久化），本 Feature 不重复 ASR。
- 输出侧复用 `NotificationChannel.external` + `delivery-projection` 脱敏接缝。
- 缺口：TTS provider、语音投影渲染层、decide 一问一答状态机（`src/speech/` 现仅有 transcription provider）。
- 语音是 Channel 输出适配，不是新的任务类型或 Conversation 入口（architecture 约束）。

## 三声道的听觉渲染

| lane     | 屏幕渲染              | 语音渲染                                                           |
| -------- | --------------------- | ------------------------------------------------------------------ |
| `say`    | 聊天正文，可流式      | 逐句播报、可打断；长回答先说结论再问「要展开吗」                   |
| `work`   | 折叠事件卡 + 抽屉下钻 | 完成才一句话摘要（结论 + 一个剩余风险 + 「要听细节吗」）；进度静默 |
| `decide` | 行动卡 + 按钮         | 显式一问一答：问句→停止播报→等待回答→匹配口头决定                  |

三条语音专属规则（合同推论，非风格选择）：

1. **带宽自律**：语音串行、易逝、无回溯。默认只播 say 与需用户决定的 decide；work 进度不播、完成才一句话；`weight=silent` 永不出声。这是 Outbox「默认安静」合同的听觉版。
2. **decide 必须显式一问一答**：语音没有按钮，「念一段话等用户点」不成立。高风险授权/接受追加复述确认（「你确认要写入笔记库吗？」），对应 APPROVAL-001 受认证 confirmation——口头「同意」同样要经受认证通道，不能由 ASR 文本直接获得产品级信任。
3. **可恢复性**：「再说一遍」「停止」必须可用；停止中断整个播报队列而非仅当前句。服务端权威记录 + 投递游标是语音的「上翻」。anchor 的语音对应物是话语内指代（「你早上说的那件事」）+ 可追问。

## 验收条件

1. 提供可替换 TTS provider（默认系统/浏览器内置），接口与 ASR provider 对称；自定义端点失败自动回退内置并显式提示，不静默失声；恢复成功后提示复位。
2. 语音渲染按 CONV-006 的 lane/weight 投影：默认只播 say 与需决定的 decide；work 进度静默、完成才一句话；`weight=silent` 永不出声。播报策略（work 摘要/静默/详情、decide 逐个问/稍后、自动播报开关）可配置。
3. decide 是显式一问一答；高风险授权/接受追加复述确认。口头「同意」与屏幕点击触发同一服务端 decide 迁移（一份权威两视图）；否定语义（「先别授权」）不得被反转为肯定。
4. 高风险接受的受认证确认由 APPROVAL-001 兜底；语音设置/口头决定不能绕过受认证 confirmation。
5. 屏幕↔语音切换无缝携带状态：未决 decide 带过来变一问一答、已决显示已处理；语音中做的决定切回屏幕已生效、「待你处理」计数同步；切换不丢失/重复事实（节点级消费游标，busy 窗口到达的事实补播）。
6. 「再说一遍」「停止」可用，停止中断整个播报队列；服务端记录 + 游标可恢复。
7. 导航与模式开关是 app 级 chrome，不随渲染器切换消失；渲染器偏好（TTS/播报策略/字幕）存客户端，服务端不记录「用户在哪个模式/什么声音」。
8. 语音唯一途径渠道（音箱/玩具）注册为 external 渠道 + 语音投影渲染器即可接入；脱敏摘要天然适合播报，evidence 细节留服务端等受认证下钻。
9. TTS/投影/切换/decide 状态机均有自动化回归，`pnpm check` 与 `pnpm smoke` 通过。

## 语音设置（渲染器偏好，非会话事实）

- TTS 引擎：默认系统/浏览器内置（本机合成不离开设备）↔ 自定义端点（端点/Key/音色）；失败回退内置 + 提示。
- 音色/语速/音调/试听；播报策略（自动播报、work 三档、decide 两档、高风险复述/直接、barge-in、字幕开关）。
- ASR 引擎/语言复用 VOICE-001 设置；尾点静默、唤醒词/连续监听属后续 Feature。
- 偏好存客户端，服务端不记录；事实与决定权威不变。

## 数据、权限与接口

- TTS 自定义端点意味着文本离开设备，external 渠道脱敏投影合同同样适用；API key 产品化应走服务端代理而非客户端明文。
- 音频输出不持久化；decide 口头决定走既有事件链路并经受认证确认。
- 沿用实例 bearer + `userId` 所有者校验；投影继承 CONV-006 隐私边界。

## 非目标

- 不实现唤醒词/连续监听（音箱形态另立 Feature）。
- 不做离线 TTS/语音克隆。
- 不实现语义级意图识别（ASR 只转录，决定匹配是受控状态机不是自由 NLU）。
- 不把渲染器偏好落服务端。
- 不绕过 APPROVAL-001 受认证确认。
- 不实现用户接受/返工持久化（GOAL-001）。

## 失败与恢复

- TTS 失败回退内置 + 提示；ASR 失败沿用 VOICE-001 可恢复提示，不创建半成品消息。
- 切换/播报中断后游标可恢复，不重复播报已消费事实。
- 回滚只需移除 TTS provider 与语音渲染接入，屏幕渲染与既有事实不受影响。

## 落地顺序

1. TTS provider + 按 lane 的话语渲染（最小闭环）；
2. decide 一问一答状态机 + 受认证确认接线；
3. 切换游标/补播与设置面；
4. 音箱/玩具渠道适配在合同稳定后另立 Feature。

交互形态（含双向同步、否定匹配、busy 补播、设置面）已在本地研究原型验证并经独立审查修复（`research/conversation-page-design/`，gitignored，不作为实现事实来源）。正式实现需在独立 Feature worktree 补自动化证据。
