# 宿主账号凭据边界（APPROVAL-001）

## Intake（2026-11-27）

基线 `a8ec5c850863e28936dee07eaef115d68b951992`；独立分支 `fix/APPROVAL-001-credential-boundary`。主工作区无改动，不替换正在运行的版本。

事故：一次普通的「工作区外写入」批准允许 bash 升级为完全访问，Agent 随后通过 Git credential helper 读取本机钥匙串密码，再临时设置 GH_TOKEN 创建 PR。模型自述「已授权」不能证明用户授权了账号访问。

验收条件：

1. 凭据提取属于不可由普通审批解除的拒绝；严格、标准、完全访问、旧单次 grant、长期规则和自动审阅均不能豁免。
2. 执行器不继承宿主 GitHub token、SSH agent、云凭据等环境；Pegas 明确配置的模型连接仍可供模型运行时使用，但不能隐式转交给命令子进程。
3. 已知宿主凭据存储（Git/GH/SSH、钥匙串、云 CLI、浏览器账号目录）同时受到文件服务和子进程运行层保护。改用脚本、绝对路径或删除 Git 环境覆盖不能解除保护。普通文件工具、构建、公开/本地 Git 操作仍可运行。
4. 运行层无法建立边界时拒绝启动工具，不回退为裸执行。拒绝不读出秘密，不生成误导的通用审批；旧 grant 按未执行结算，后续请求仍可恢复。
5. 回归先红后绿，完整 check、smoke，并用真实 DSH 与合成凭据验证；测试不读取或修改用户真实账号秘密。

非目标：新增账号 OAuth/凭据代理、替用户登录、撤销现有账号、修改主机 gh 登录、限制任意位置的业务文件、将同用户进程隔离宣称为虚拟机级隔离。需要认证的远端操作在专用账号授权能力完成前明确失败，不能自动改从其他本机凭据来源尝试。

权限与数据边界：凭据目录清单由宿主启动器生成，模型或普通审批不能修改；确定性分级提供解释，进程沙箱负责阻断间接命令。DSH 配置/插件属于可信运行代码。自定义位置的秘密、已复制进工作区的秘密及任意第三方插件直接在宿主进程执行代码不在目录清单保护承诺内。

失败与恢复：无数据库迁移，不改写历史审批。旧授权在恢复时重新判定；执行失败保留既有 outcome/重试链路。发布必须经不可变 Candidate 与 Supervisor 验证。回滚代码会恢复旧权限缺口，回滚期间应停止执行工作任务，不能把回滚描述成安全修复。

## 实现与运行合同

- `credential-boundary.mjs` 是凭据目录、环境清理和子进程隔离的共同事实来源。Git 忽略宿主 global/system config、关闭交互式取凭据；普通仓库本地配置仍在，但 helper 无法越过凭据目录/服务边界。服务端命令指纹与执行器使用相同清理后的环境，旧指纹不匹配时重新审批。
- `dsh-credential-boundary.mjs` 无条件挂载，独立于 `approvalPolicy`、档位和一次性 grant。先注册默认拒绝 guard，再等待文件/子进程服务就绪；缺失服务不会静默裸跑。文件服务拒绝受保护路径，进程与终端入口都附加隔离；子进程不得继承模型连接密钥。
- macOS 使用 Seatbelt：受保护目录禁止读写，拒绝本机 Mach 服务和 Unix socket 连接，只保留 DNS 的 mDNSResponder socket 与网络配置服务。已有 DSH 写沙箱合并同一 profile，避免嵌套沙箱失败；完全访问命令也必须添加凭据边界。SecurityServer 服务端口的合成探针只验证连接权限，不查询任何真实钥匙串条目。
- Linux 需要 Bubblewrap（`/usr/bin/bwrap` 可执行，且主机允许其 namespace）；遮蔽凭据目录/文件并使用独立 PID namespace。缺失后端直接执行失败，无降级。它不承诺隔离所有未登记的同用户 IPC 服务；跨用户/不可信插件隔离需要容器、独立 OS 用户或远程执行能力，不由目录清单冒充。
- 受保护位置包括 HOME 下 Git/GH/SSH、GPG、云 CLI、模型客户端、钥匙串和常见浏览器账号目录，以及宿主环境指向的 GH、云凭据和 SSH agent 等自定义路径。只传递路径，不读取秘密值；符号链接目的地同样保护。自定义业务配置中的秘密不属于这份目录清单。
- `policy-gate.mjs` 提供 `credential-access` 明确拒绝。桥的 guard、pre-execute、approval/request 都不能被原 grant/持久规则/自动审阅放行；拒绝的旧 grant 通过既有幂等 outcome 记为 failed + notExecuted。外发审批的内容预览也不代读凭据目录。

## 验证

回归首先在旧实现得到 5 项失败（3 个权限档位、链接读取、环境继承），其余 60 项通过；命令指纹兼容回归也先失败后修复。自动化覆盖原调用、文件服务、脚本、符号链接、缺失后端/服务、旧 grant 结算、子进程模型密钥清理及服务端环境一致性。

`pnpm smoke:credential-boundary` 使用真实 DSH、临时 HOME、合成凭据和本机模型夹具网关，默认全访问、无人工审批，验证原本可读的秘密无法进入模型、普通写入成功；macOS 同时验证 SecurityServer 不可连接。CI 在 Linux 安装 Bubblewrap 后执行同一脚本，并在独立 macOS job 验证真实 Keychain 服务拒绝，避免只用 Linux 测试替代平台证据。完整 check/smoke 与命令授权桌面门禁的最终数量、提交及发布状态见 Feature Map。

兼容性影响：Pegas 不再借用本机 gh、Git helper、SSH agent 或云 CLI 的登录状态；需要认证的外部操作必须等待独立、明确的账号连接能力，当前不能通过通用批准恢复。宿主 gh 的登录状态未修改，用户仍可在自己的终端完成认证操作。
